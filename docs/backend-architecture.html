後端架構

後端是包在 App 裡的一個小伺服器：收下使用者的話，啟動 Agent 讓它用畫布工具直接動手；另外負責語音轉文字。

已定模組切分、端點、記憶的做法
已定請求格式、設定、錯誤種類（2026-11-27 確認）
還沒做程式（只有骨架）

整個 App 的架構見 architecture.html；舊的 iPad／獨立伺服器版本在 archive/backend-architecture.html（舊版）。資料更新日 2026-11-27。點圖上的方塊可以跳到它的說明。

2026-11-27 確認的 11 件事 已定

  1. /generate 的請求帶四樣：使用者的話、筆記資料夾、按下去當時選了哪些東西、那一刻的截圖。
  2. 回應和錯誤的種類（一張表）。
  3. 同一時間只跑一個 AI 請求，第二個回 busy。
  4. 新筆記一開始就先選位置、建資料夾，這樣記憶一開始就有地方放。
  5. 記憶檔只有一個：memory.jsonl。

  10. Log 會記使用者說的那句話。

3. 一次 /generate 請求

一個請求從進來到回應，在伺服器裡走八步。

1 Request in

Swift 外殼送 POST /generate，帶 token、使用者的話、筆記資料夾、選了哪些東西、截圖。

2 Check token

index.ts 比對 token，不對回 401。

3 Build prompt

規則 + 使用者的話 + 「使用者選了這些編號」+ 截圖。話是空的就用「你自己判斷最適合的形式」。

4 Open memory

在筆記資料夾找到這份筆記的對話紀錄；沒有就是第一次。

5 Start Agent

啟動 Claude Code，只給畫布的六個工具。先看它實際拿到的工具清單，多出別的就停下，回 unexpected_tools。

6 Agent works

AI 讀畫布、放和改東西，每一步直接出現在畫布上。對話紀錄邊做邊寫進筆記資料夾。App 斷線或按取消，就叫 Agent 停下。

7 Log

記一行 log。

8 Respond

回 done 和 AI 的一兩句說明，或回錯誤。不逐字串流。

Claude Code（第 6 步裡）

真正在跑 Agent 的程式。它決定下一步叫哪個畫布工具，例如先 get_scene 再 add_elements。

Canvas MCP（第 6 步裡）

收到呼叫就讀或改 App 的畫布，把結果交回 Claude Code。例如 get_scene 回畫布上有什麼。

request 可以是空的空字串：使用者直接按「幫我看看」。
為什麼帶 selectedIds已定 畫布不鎖，從按下去到 AI 讀畫布之間，選取可能已經變了。沒選東西就是空陣列。
為什麼帶 screenshot已定 PNG，放在 JSON 裡的 base64 字串，長寬設上限。有選取就截選取範圍加一點邊，沒選取就截目前看到的畫面；由 Swift 外殼請畫布頁面輸出。交給 Agent SDK 時本來就要 base64，所以伺服器原封不動轉交。手繪和貼上的圖片只有看圖才懂，附上就不用靠 AI 自己想到去看。多花的 token 很少。
截圖不寫進記憶檔已定 未驗證 記憶轉接器寫檔時，把圖片換成一行字「這裡原本有一張截圖」。記憶檔只存文字。下次請求 AI 看不到上次的截圖，但有那次的文字紀錄和這次的新截圖。要先試：紀錄裡的圖不見了，SDK 接續對話會不會出問題。
畫布的資料不放進請求每個東西的位置、大小、文字，AI 自己用 get_scene 讀；改完想檢查結果時用 render_image 再看一次。已定

一份筆記是一個資料夾：畫布檔由 App 寫，記憶檔由伺服器寫。

Canvas file 已定

標準的 .excalidraw，可以拿去別的地方用，裡面沒有我們加的東西。伺服器不碰它。

memory.jsonl 已定

Agent SDK 的對話紀錄，一行一筆。每次請求接續它，所以 AI 記得這份筆記以前說過什麼、做過什麼，可以叫它把東西還回來。

Swift shell

使用者按 ⌘S 時，App 把畫布寫進畫布檔。

Bun server (Memory)

請求進行中，memory.ts 把對話紀錄寫進 memory.jsonl。畫布檔它不碰。

壓縮太長時 SDK 會自動把舊的部分整理成摘要，我們不寫壓縮。已定
只用一個檔未驗證 實驗時是兩個檔（一個記對話的編號，一個記內容）。要試試能不能從記憶檔本身讀出編號；不行就保留那個小檔。
新筆記已定 按 New note 時先選位置、建好資料夾。否則第一次叫 AI 時記憶沒地方放。
記憶和 ⌘S已定 記憶在請求當下就寫，不等 ⌘S。結果是：使用者沒存檔就關掉，記憶裡會有畫布檔裡沒有的事。先接受。
檔案大小記憶檔會一直變大（實驗裡兩次請求約 490 KB），保留多久還沒決定。
另一份副本第一次請求會在 ~/.claude/ 底下另外留一份副本，接受。已定
壓縮之後AI 還記得多少：未驗證

6. 啟動和設定

App 打開時由 Swift 外殼啟動伺服器，把設定交給它；App 關掉，伺服器跟著結束。

1 App opens

使用者打開 App，Swift 外殼先跑起來。

2 Shell starts server

外殼啟動伺服器程式，用環境變數把設定交給它（下面那個 env 框）。

3 Server listens

伺服器只聽本機 127.0.0.1，等外殼送請求。少了 ACCESS_TOKEN 就不啟動。

4 App quits

App 關掉，伺服器跟著結束。

env

外殼交給伺服器的環境變數。每一個的意思見下表。

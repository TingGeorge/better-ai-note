後端架構

後端是一個小的、不存狀態的 Bun 伺服器。它收下圈選的圖片，組好提示詞，呼叫模型，再把結果串流回 iPad。

語音需求

用講的時候，先把語音轉成文字放回輸入框，使用者確認後才送出。

聽寫，不是語音對話錄完整段再上傳；需求只有幾秒鐘，不需要即時串流。
文字先回輸入框中英夾雜的術語容易聽錯，使用者可以先改。
/generate 不變它還是只收圖片和文字。
音檔不留轉完文字就丟掉，不寫進 log。

連線與部署

伺服器跑在 Docker 裡；每個請求都要帶 token，而且連線要加密。

Token 放哪伺服器 .env 的 ACCESS_TOKEN，一串長亂數。
iPad 怎麼存在設定頁輸入伺服器網址和 token，存進 Keychain。
怎麼帶每個請求加 Authorization: Bearer <token>。
伺服器怎麼擋不符就回 401；沒設 token 就拒絕啟動。
不需要帳號、登入、JWT、OAuth。
啟動docker compose up -d；compose 讀 .env，掛一個 volume 放 log。

已經決定

  • 語音：伺服器接 STT API，iPad 只負責錄音。
  • Access token：要，一個共用 token。
  • 模型層：用 pi-agent-core。畫圖表、心智圖這類任務比較複雜，讓模型可以呼叫工具、分幾步完成。每個請求開一個新的 Agent，做完就丟，伺服器還是不存狀態。
  • 統計數字：平均數、標準差由 calc 工具用程式計算，不讓模型心算。
  • 斷線就停：App 斷線或按取消時，伺服器叫 Agent 停下，不再呼叫模型。斷線後算完的結果沒有地方送。
  • 部署：Docker。
  • 連線加密：Tailscale。伺服器不對外公開，只有你的裝置連得到；iPad 和伺服器都要裝 Tailscale。
  • Log：只留 AI 的輸出和請求的基本資料，不留圖片；出錯時看不到模型當時看到什麼。
  • 輸出格式：Typed block，SwiftUI 把每一種原生畫出來；每一種都要寫一個畫法。 
    {
  kind: "table" | "chart" | "steps"
      | "mindmap" | "summary",
  data: ...
}
